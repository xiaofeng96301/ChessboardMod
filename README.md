# Chessboard Mod

Minecraft 棋盘游戏模组：**六种棋类**（中国象棋、国际象棋、五子棋、井字棋、飞行棋、板棋家族），
共 **八块棋盘**。玩法偏「实体棋盘」：棋盘是方块，棋子是立体模型，选中会抬起、走子会飞过去、
被吃掉的棋子会消失。

**同一个 jar 同时支持 MC 26.1.2 与 26.3。**

- 模组 ID：`chessboard`
- 依赖：Minecraft 26.1.2 + NeoForge 26.1.2.76（26.3 亦可）、Java 25

## 功能一览

- **八块棋盘** — 中国象棋（10×9）、国际象棋（8×8）、五子棋（15×15）、井字棋（3×3）、
  飞行棋（15×15）、板棋三块（7×7 / 9×9 / 11×11）
- **完整交互** — 空手右键棋盘格下棋；选中的棋子抬起，走子沿棋盘飞过去，被吃掉的棋子消失
- **立体棋子** — 全部是 Blockbench 3D 模型：国际象棋六种棋型（王/后/象/马/车/兵）× 黑白两色；
  中国象棋是圆片 + 汉字（帅/将、仕/士、相/象、马、车、炮、兵/卒），红黑双色；
  飞行棋四种队色；板棋三种（护王兵 / 王 / 捉王兵）
- **板棋夹击吃子** — 落子后**夹在中间的敌子**被吃掉（不是「踩上去吃」），一次落子可夹多颗
- **胜利提示** — 象棋帅（将）被将军时自己跳一下、被吃后赢家全体棋子跳起晃动；国际象棋赢家棋子
  原地自转一圈；板棋王到边缘 / 王被吃时赢家全体跳起晃动；五子棋连五那五颗跳起晃动。
  每块棋盘都有界面开关，**默认关**；而且只是提示，不封盘
- **飞行棋** — 点棋盘正中的骰子掷 1~6（带翻滚动画）、同格可堆叠多队、默认开局吃子回机库、和平开局不吃子
- **特殊开局** — 中国象棋暗棋 / 全暗棋（带翻面动画）、五子棋随机灰子障碍、飞行棋和平开局、
  板棋四种变体开局
- **棋盘样式（皮肤）** — 界面里每个棋盘、每种棋子颜色各有一个槽；把方块拖进去立刻上色
- **管理界面** — 悔棋、重置、导入 / 导出棋局码、切换开局方式
- **右键侧面开菜单** — 可选：右键棋盘**侧面**直接开界面，上下面仍正常落子
- **指令系统** — `/chessboard` 系列指令可远程操作
- **NBT 持久化** — 挖掘棋盘保留棋局状态与样式，带数据掉落

## 六种棋类

### 中国象棋（10×9）

- **棋子** — 圆片 + 汉字，红黑双色；圆片没有正反面，朝向跟着汉字走（会按阵营翻转）
- **开局方式** — 默认 / **暗棋**（双方各自随机打乱自己棋子的类型位置，全部盖成背面）/
  **全暗棋**（所有人的棋子随机打乱，阵营也随机）
- **暗棋翻面** — 点击盖着的棋子会翻开，前半程显示背面模型、后半程显示正面；导出棋局码时会自动
  揭开，避免隐藏位破坏编码
- **将军提示** — 帅（将）被对方的棋子攻击到时，它会自己跳一下（按象棋的攻击路线判：车直行、
  炮翻山、马别腿、兵过河能横走、帅对脸；**只用来提示，不限制走法**）。暗棋盖着时身份未知，不参与
- **胜负** — 帅（将）被吃掉后，赢家**全体棋子**跳起晃动
- **走法** — 不做合法性判定（见[已知限制](#已知限制)）

### 国际象棋（8×8）

- **棋子** — 六种棋型各一套 3D 模型：王、后、象、马、车、兵；白方浅色木、黑方深色木
- **开局方式** — 只有默认
- **胜负** — 一方的王被吃掉后，赢家全体棋子**原地自转一圈**
- **走法** — 不做合法性判定

### 五子棋（15×15）

- **棋子** — 黑白圆片（另有随机开局用的灰色障碍子）
- **开局方式** — 默认 / **随机开局**（在棋盘上随机撒 3~10 个灰子当障碍，黑先）
- **胜负** — 连成五子时那五颗会跳起并左右晃动一下；判定**默认关**，可在棋盘界面里用
  「胜利判定」按钮打开（开关跟着这块棋盘走）
- **悔棋** — 随机开局的灰子是**逐颗**记进历史的，所以悔棋也逐颗回退

### 井字棋（3×3）

- **棋子** — 一面是圈、一面是叉的扁平棋子；叉方渲染时把模型翻面
- **开局方式** — 只有默认（棋盘是空的）

### 飞行棋（15×15）

- **棋子** — 四色（红 / 黄 / 蓝 / 绿），落在四个角的机库里
- **棋盘** — 外圈循环跑道 + 中央十字 + 四角机库，颜色按红蓝黄绿循环
- **掷骰子** — 空手右键**棋盘正中的骰子格**掷 1~6，骰子会翻滚着落地；骰子不吃皮肤，
  永远用模组自己的点数贴图
- **两种开局** —
  - **默认**：同队可以堆叠在同一格；落到敌方棋子上会把**整格**敌机送回各自机库（吃子），
    然后自己落一架
  - **和平**：敌我共格堆叠共存，**永不发生吃子**（适合摆局面用）
- **堆叠** — 和平开局下同一格里可能停着几个阵营的飞机；反复点击同一格会在这一格里的
  各颗棋子之间**轮换选中**
- **走法** — 有自己的规则（堆叠 + 送回机库 + 整格处理），不走框架那套「异色直接覆盖」
- **胜负** — 没有做（见[已知限制](#已知限制)）

### 板棋家族（Tafl）

北欧的「王与护卫」棋，三块棋盘、四种开局变体。**共用一套外形**：王在正中、护王方若干兵围着王、
捉王方在四边各有营地。

| 棋盘 | 变体 | 护王方 | 捉王方 |
|---|---|---|---|
| 7×7 | 爱尔兰板棋（Brandubh） | 王 + 4 名卫士 | 8 名，两两贴着四角 |
| 7×7 | 苏格兰板棋（Ard Ri） | 王 + 8 名卫士（八邻格） | 16 名，每边 3+1 |
| 9×9 | 萨米板棋（Tablut） | 王 + 8 名卫士（十字） | 16 名，每边 4（T 形营地） |
| 11×11 | 挪威板棋（Hnefatafl） | 王 + 12 名卫士 | 24 名，每边 4+2 |

- **棋子** — 护王兵（浅木）、王（白桦）、捉王兵（深色橡木）
- **夹击吃子** — 落子后看这颗棋子的**四个正交方向**：紧邻的敌子如果另一侧也紧邻着己方棋子，
  就被夹死吃掉；一次落子最多夹掉四颗。抬着棋子去点敌子**什么都不发生** —— 板棋没有
  「踩上去吃」那套
- **胜负提示** — 王走到棋盘**边缘或四角** → 护王方全体棋子跳起晃动；王**被吃** → 捉王方全体跳起晃动
- **还没做的规则** — 车走法（不限距离直线走）、王的四面围死、王座与四角当「墙」参与夹击。
  现在王跟普通棋子一样，两颗夹住就没了

## 操作

| 操作 | 方式 |
|------|------|
| 下棋 | 空手右键点击棋盘格点 |
| 抬起 / 放下棋子 | 点一下选中（棋子抬起），再点同一格放下 |
| 换选 | 抬着棋子点另一个自己的棋子 |
| 掷骰子（飞行棋） | 空手右键点击棋盘正中的骰子格 |
| 轮换选中（同格多颗） | 反复点同一格 |
| 打开样式界面 | 默认 **SHIFT + 右键**（按键可在按键设置里改，默认左 Shift） |
| 右键侧面开菜单 | 可选开关：界面里的按钮，或配置文件（默认关，见下） |

**配置**（`config/chessboard-client.toml`，也可在界面的 Mod 配置里改）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `rightClickOpensMenu` | `false` | 开：右键棋盘**侧面**直接开样式界面（上下面仍正常落子）。关：只有 SHIFT + 右键才开 |
| `boardRenderDistance` | `32` | 超过这个距离（方块）就不再渲染棋盘上的**动画棋子与文字**。静止棋子烘焙在区块几何里，跟客户端「渲染距离」走 |

**样式界面里能做的事**：悔棋、重置棋盘、导入 / 导出棋局码、切换开局方式、
把方块放进皮肤槽给棋盘和棋子上色，以及切换**胜利判定**开关。

**胜利判定开关**（有胜利效果的棋类都有：中国象棋、国际象棋、五子棋、板棋）：它是**棋盘自己的属性**
—— 跟着棋盘存盘、跟着方块实体同步，所以两块棋盘的设置互不影响。**新棋盘一律默认关**
（不默认就跳/划线），要看得自己去界面里打开。

## 棋盘样式（皮肤）

给棋盘「换木头」的正规做法，比换模型贴图省事：

- 界面右侧按**槽位**排列：棋盘一个槽，每种棋子颜色一个槽
  （中国象棋 1 个、国际象棋 2 个、五子棋 3 个、飞行棋 4 个、板棋 2 个）
- 把方块拖进槽里**立刻上色**；拿出来、关界面都不会退回默认，只有左边那条
  **「重置样式」**会把方块还给你并恢复默认外观
- 换棋盘样式时**底板顶面与格线图案是一起换的** —— 棋盘贴图本身只画了格子线（透明底），
  真正的底色在底板那一层，只换一层的话格子线底下会永远透出木头色
- 样式随棋盘存进物品 NBT，挖下来再放下仍然保留
- 骰子不吃皮肤，永远用模组自己的点数贴图
- **槽位编号是冻结的**（老存档里的槽位号不能变），新增棋类只能往后面**追加**

## 指令

指令没有额外权限要求。`<x> <y> <z>` 都是棋盘方块的坐标。

```
/chessboard click        <x> <y> <z> <row> <col>  — 模拟点击某一行列（调试用）
/chessboard undo         <x> <y> <z>              — 悔棋
/chessboard reset        <x> <y> <z>              — 重置棋盘（按该棋盘的默认开局）
/chessboard import       <x> <y> <z> <code>       — 导入棋局码（格式不对会拒绝，且不改动棋盘）

/chessboard darkstart    <x> <y> <z>              — 暗棋开局（中国象棋）
/chessboard fulldarkstart <x> <y> <z>             — 全暗棋开局（中国象棋）
/chessboard randomstart  <x> <y> <z>              — 随机开局（五子棋）
/chessboard peacefulstart <x> <y> <z>             — 和平开局（飞行棋）

/chessboard tablut       <x> <y> <z>              — 萨米板棋开局（9×9）
/chessboard brandubh     <x> <y> <z>              — 爱尔兰板棋开局（7×7）
/chessboard ardri        <x> <y> <z>              — 苏格兰板棋开局（7×7）
/chessboard hnefatafl    <x> <y> <z>              — 挪威板棋开局（11×11）
```

棋盘不支持的开始方式会拒绝执行并回一句话（例如拿 7×7 的棋盘开萨米板棋）。

## 棋局码

界面里的「导入 / 复制」走的是纯文本棋局码，按棋类带一个前缀：

| 前缀 | 棋类 |
|---|---|
| `xq` | 中国象棋 |
| `ic` | 国际象棋 |
| `wz` | 五子棋 |
| `jz` | 井字棋 |
| `fx` | 飞行棋 |
| `tb` | 板棋 |

- 中国象棋导出时会自动揭开暗棋，避免隐藏位破坏编码
- 飞行棋的编码向后兼容：旧的 `fx` 码仍然能导入（新格式是 `fxv2`）
- 导入失败（格式不对、不是这个棋类）会**拒绝且不改动棋盘**，不会把局面弄坏

## 悔棋与历史

- 历史按「**前后两代棋盘的变化格子**」记录，所以走子、吃子、暗棋翻面都能一步还原
- 上限 **100 步**，超出后从最早的一步开始丢
- 掷骰子**不进历史**（骰子不可悔）
- 随机开局的灰子是逐颗记录的，悔棋也逐颗回退

## 存档与兼容

- 棋盘的状态（棋子、选中、历史、样式、飞行棋的和平标志、胜利判定开关）全部存在方块实体的 NBT 里，
  挖掘时按潜影盒那套（`collectComponents` / `applyComponents`）搬进物品，放下再还原
- **棋盘方块 ID、NBT 键、棋局码前缀、皮肤槽位编号都是冻结的契约**：改了会让老存档里的
  棋盘读不出来或串样
- 棋子编码本身向后兼容（例如飞行棋单架仍然是 `1..4`），所以早期存档不需要迁移

## 渲染与性能

棋盘上的棋子有**两条渲染路径**，必须共用同一套变换与光照参数：

1. **静止棋子** —— 烘焙进区块几何（跟随客户端渲染距离，几乎不花每帧开销）
2. **动画中的棋子** —— 方块实体每帧重画（抬起 / 落下、走子飞行、暗棋翻面、骰子翻滚、
   胜利跳动）

两条路径只要有一点不一致，动画结束、棋子从逐帧交还给区块几何的那一瞬间就会**跳一下**，
所以它们都走 `ChessboardPieceGeometry` 里那一份共用变换。

- `boardRenderDistance`（默认 32）只影响第 2 条路径上的动画棋子与文字
- **四边形预算**：单个区块里棋子面数超过 `PIECE_QUAD_BUDGET`（650k 四边形）时，
  只画棋盘本体、不画棋子并打一条 WARN。这是为了防 26.3 的顶点缓冲硬上限 ——
  26.3 把区块顶点上传换成固定 98 MiB 的 staging buffer，**超了直接抛异常崩游戏**（不降级）。
  按实测密度，一个区块大约能放 100~200 块满员棋盘
- 界面里把方块放进皮肤槽是用**顶点色**做染色的：顶点色是乘法、8 位提亮不了，
  所以只能做「目标均色 / 源均色」的逐通道比值，源贴图里没有的通道染不出来

## 开发

### 环境

- **Minecraft** 26.1.2（NeoForge 26.1.2.76），**Java** 25，**Gradle** 9.x
- 规则类是**纯 Java**（不 import 任何 Minecraft 类型），可以脱离游戏跑自测（需要 JDK 27）

### 构建与运行

```bash
./gradlew build        # 构建
./gradlew runClient    # 启动客户端
./gradlew runServer    # 启动服务端
```

### 自动化检查

```bash
# 方块 / 物品 / 模型 JSON 由脚本生成，是这几类资源的唯一真相来源：
python tools/gen_chessboard_resources.py            # 生成
python tools/gen_chessboard_resources.py --check    # 只校验（提交前用）

# 规则自测（纯 Java，不用开游戏；结果写在 build/*_result.txt）
jshell --class-path build/classes/java/main -q tools/check_tafl_start.jsh     # 板棋开局与格心
jshell --class-path build/classes/java/main -q tools/check_tafl_capture.jsh   # 板棋夹击吃子
jshell --class-path build/classes/java/main -q tools/check_flight_rules.jsh   # 飞行棋规则与骰子
jshell --class-path build/classes/java/main -q tools/check_win_conditions.jsh # 各国胜利判定（含将军）

# 跨版本核对：拿编译产物去 26.3 的运行时 jar 里逐个查方法/字段引用
python tools/check_26x_abi.py "<26.3 客户端 jar>" --extra "<neoforge universal jar>"
```

跨版本脚本的用法有个诀窍：它会有假阳性（继承链解析不足），所以**先跑一次记下报告行数当基线，
改完再跑 —— 行数没变才算干净**，别逐条去修。

### 代码分层（改代码前先看一眼）

```
com.chessboard.api     对外稳定层：BoardGameLogic（规则接口）、DiceBoard（骰子能力接口）。
                       只依赖 java.* 与原版类型，不 import 框架类 / client 包。
com.chessboard.game    内部规则实现：纯 Java，可 jshell 自测；不出现任何 Minecraft 类型。
client.renderer        渲染：两条路径共用 ChessboardPieceGeometry 的变换与度量。
block / blockentity / menu / network / SkinData   框架层：面向 api 接口，
                       禁止出现 instanceof XxxLogic（按棋类分派）——「有没有骰子」这类
                       要问 instanceof DiceBoard（能力接口），新棋类自动适用。
```

### 新增一种棋类要动哪些地方

1. `game/` 里实现 `BoardGameLogic`（落子类可直接继承 `PlaceGameLogic`）
2. 在 `client/renderer/PieceModels` 里**登记一条**：这个棋类用哪些方块状态当棋子模型
3. 在 `SkinData` 里**追加**槽位编号（只能往后加，不能改号）
4. 资源：把棋盘与棋子的模型加进 `tools/gen_chessboard_resources.py` 的字典，跑生成
5. `ChessboardMod` 里注册棋盘方块（`registerBoard`）、物品、创造标签、以及各种开局指令
6. 写一份 `tools/check_<棋类>_*.jsh` 自测 —— 规则是纯 Java，这一步很便宜

框架层一行都不用改：棋盘方块、方块实体、菜单、网络、两条渲染路径都是通用的。

### 跨版本（26.1.2 / 26.3）注意事项

同一个 jar 要跑两版，下面几条是这个项目实际踩过的坑（细节见 `tools/check_26x_abi.py` 的文件头）：

- **别引用原版的数字 / 字符串常量**（带 `ConstantValue` 的字段会被编译期内联，编译和加载都不报错，
  运行期悄悄变成错的值 —— 26.3 重编过整套键码）。要按名字**运行期查表**
- **别引用 `Blocks` 里的「颜色」常量**（`BLACK_CONCRETE` / `BLACK_WOOL` … 26.3 全删了，只剩黑石那一族）。
  两版都有的深色方块用 `OBSIDIAN`
- **旋转统一走 `ChessboardPieceGeometry.rotateBy`**（26.3 删了 `PoseStack.mulPose(Quaternionfc)`，
  而 26.1.2 没有 `rotate(...)`，只有 `mulPose(Matrix4fc)` 两版都在）
- **带 `RenderPipeline` 参数的渲染重载不要用**（类型换了包，字段描述符跟着变 → `NoSuchFieldError`）

### 资源与贴图

- 方块状态 / 模型 / 物品模型 JSON 由生成脚本负责，**不要手写**；生成器是这些资源的唯一真相来源
- **手工贴图不许覆盖**：飞行棋棋盘贴图与板棋三块棋盘贴图是手绘的，没有任何脚本会写它们
  （生成脚本只管 JSON，飞行棋脚本的棋盘闸门默认拒绝写入，`--force-board` 才写且会先备份）。
  改动它们前先看 `tools/backup/`
- 板棋棋盘的**格子参数是照着手绘贴图量出来的**（作者按整数格画的，三块棋盘格宽不同）。
  贴图重画过就要重新量格心，并同步改 `TaflLogic` 里那三个常量与 `tools/check_tafl_start.jsh`
  里钉住的数 —— 对不上的表现是棋子渐渐偏出格子，最外圈最明显

## 已知限制

- **走法不做合法性判定**：除了板棋的夹击吃子，棋子可以走到任意空格（也允许选择对方的棋子来搬）。
  这个模组做的是**棋盘、开局摆放与棋子交互**，不是完整规则引擎 —— 摆局面、推演、当装饰都行
- **没有 AI / 电脑对手**
- **胜负判定只是「表演」**：赢了不封盘，也不阻止继续走子 —— 只是赢家棋子跳一下 / 自转一圈 /
  划一条线。真正的终局规则（将军不能不管、将死封盘、飞行棋进终点……）都没做
- 有胜利效果的棋类（中国象棋、国际象棋、五子棋、板棋）每块棋盘都能在界面里开关胜利判定，
  而且**新棋盘一律默认关**；飞行棋与井字棋没有胜利效果，也就没有这个按钮
- **板棋只做了夹击吃子与「王到边缘/王被吃」的提示**：车走法、四面围王、王座与四角当「墙」都没做
